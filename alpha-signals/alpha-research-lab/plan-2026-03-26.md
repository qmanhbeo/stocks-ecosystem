     Plan: Comprehensive LLM News Feature Extraction

     Context

     The news path has been partially explored (C1 keyword sentiment — sparse, weak).
      LLM can extract far richer structured features than keywords. Since we're
     already paying the inference cost per article, we should extract everything
     useful in one pass to avoid re-running later. Goal: produce dense date-level
     market narrative features (100% coverage, no sparsity) plus enriched ticker-day
     features for RL use.

     Local Ollama is available at localhost:11434 with qwen2.5-coder:7b
     (benchmarked: ~0.55s/article in batches of 10).

     ---
     Architecture

     Two scripts:

     1. data_tools/extract_llm_news_features.py — reads cafef JSONL files,
     calls Ollama in batches, writes per-day JSONL cache to data/llm_cache/
     2. data_tools/build_llm_news_features.py — reads cache, builds two output
     parquets

     ---
     Per-Article Extraction Schema

     Each article → one JSON object in the LLM response array:

     {
       "id": "2023-01-15_042",
       "tickers": ["FPT", "VNM"],
       "sentiment": 1,
       "confidence": 2,
       "event_type": "earnings_beat",
       "magnitude": 2,
       "is_forward_looking": false,
       "market_tone": 0
     }

     Fields:
     - id: article identifier (echoed from input for alignment)
     - tickers: list of VN stock tickers mentioned (from title + body), empty list
     if none
     - sentiment: -1 (negative), 0 (neutral/unclear), 1 (positive) — company-level
     - confidence: 0 (can't tell), 1 (probably), 2 (clearly)
     - event_type: one of 34 event types (see taxonomy below)
     - magnitude: 0 (minor), 1 (moderate), 2 (significant/major)
     - is_forward_looking: true if event is announced/planned, false if already
     happened
     - market_tone: -1/0/1 — overall market sentiment (not company-specific)

     Event Type Taxonomy (34 types)

     Earnings/Financial:
     - earnings_beat — profit above expectations
     - earnings_miss — profit below expectations
     - earnings_neutral — in-line or no expectation
     - revenue_growth — revenue increase reported
     - revenue_decline — revenue decrease reported
     - guidance_raise — forward guidance upgraded
     - guidance_cut — forward guidance cut
     - dividend_announce — dividend declaration
     - debt_issue — bond/loan issuance
     - debt_concern — debt problem, missed payment

     Capital Events:
     - rights_issue — new share issuance / rights offering
     - buyback — share repurchase program
     - merger_acquisition — M&A activity
     - divestiture — asset sale / stake sale
     - ipo_listing — IPO or new listing

     Corporate Actions:
     - management_change — CEO/chairman/board change
     - insider_buy — insider purchase disclosed
     - insider_sell — insider sale disclosed
     - contract_win — new contract or project awarded
     - contract_loss — contract lost or cancelled
     - partnership — strategic partnership announced
     - expansion — capacity expansion / new facility
     - legal_issue — lawsuit, investigation, fine

     Regulatory/Macro:
     - regulatory_approval — license granted, project approved
     - regulatory_block — license denied, project blocked
     - policy_positive — government policy favorable to sector
     - policy_negative — government policy unfavorable to sector
     - rate_change — interest rate decision
     - fx_move — significant VND/USD or currency move
     - commodity_price — oil/gold/commodity price event
     - macro_indicator — GDP, CPI, PMI data release

     Market Structure:
     - index_inclusion — added to index / ETF
     - index_exclusion — removed from index / ETF
     - other — newsworthy but doesn't fit above
     - no_event — general news, no specific event

     ---
     Batch Prompt Template

     You are a Vietnamese financial news analyzer. For each numbered article, output
     a JSON object with these fields: id, tickers, sentiment (-1/0/1), confidence
     (0-2), event_type (from the taxonomy), magnitude (0-2), is_forward_looking
     (bool), market_tone (-1/0/1).

     Event types: earnings_beat, earnings_miss, earnings_neutral, revenue_growth,
     revenue_decline, guidance_raise, guidance_cut, dividend_announce, debt_issue,
     debt_concern, rights_issue, buyback, merger_acquisition, divestiture,
     ipo_listing, management_change, insider_buy, insider_sell, contract_win,
     contract_loss, partnership, expansion, legal_issue, regulatory_approval,
     regulatory_block, policy_positive, policy_negative, rate_change, fx_move,
     commodity_price, macro_indicator, index_inclusion, index_exclusion, other,
     no_event

     Output ONLY a JSON array of objects, one per article. No explanation.

     [1] id=2023-01-15_042
     Tiêu đề: FPT báo lãi quý 4 tăng 28% so với cùng kỳ
     Tóm tắt: Tập đoàn FPT công bố lợi nhuận sau thuế quý 4/2022 đạt 1.850 tỷ đồng...

     [2] id=2023-01-15_043
     Tiêu đề: Thị trường chứng khoán giảm điểm do lo ngại lãi suất
     Tóm tắt: VN-Index kết thúc phiên giao dịch giảm 12 điểm...

     Parameters: temperature=0, num_predict=2048, batch size=10.

     ---
     Script 1: data_tools/extract_llm_news_features.py

     Input: data/news/cafef/raw/YYYY-MM-DD.jsonl
     Output: data/llm_cache/YYYY-MM-DD.jsonl (one JSON object per article)

     Key logic:
     1. Find all dates in data/news/cafef/raw/ sorted chronologically
     2. Skip dates where data/llm_cache/YYYY-MM-DD.jsonl already exists (resume
     safety)
     3. Filter articles: only process if article has section field containing
     financial keywords (chứng-khoán, doanh-nghiep, tai-chinh). Skip pure
     macro/sports/society. Estimate: reduces ~40k/day to ~4.2k/day
     4. Build batches of 10 articles, construct prompt, call Ollama /api/generate
     5. Parse JSON array from response; handle parse failures gracefully (log, store
     nulls)
     6. Write to data/llm_cache/YYYY-MM-DD.jsonl.tmp, then rename to .jsonl
     (atomic write)

     CLI:
     python data_tools/extract_llm_news_features.py [--date-from YYYY-MM-DD]
     [--date-to YYYY-MM-DD] [--batch-size 10] [--model qwen2.5-coder:7b]

     Error handling:
     - Ollama timeout (30s per batch): log batch, store event_type=null for all
     articles in batch
     - JSON parse failure: try to salvage partial results, log failure count per day
     - Resume-safe: only atomic-rename completed days

     ---
     Script 2: data_tools/build_llm_news_features.py

     Input: data/llm_cache/YYYY-MM-DD.jsonl files
     Output:
     - data/features/xs_llm_news_ticker_day.parquet — sparse ticker-day features
     - data/features/xs_llm_news_market_daily.parquet — dense date-level market
     features

     Output 1: xs_llm_news_ticker_day.parquet

     Grid: (trading_day, ticker) — same 826k-row grid as H93

     Columns:
     - llm_sentiment_raw — raw -1/0/1 (0 if no news that day)
     - llm_confidence — max confidence of articles mentioning ticker
     - llm_sentiment_conf_weighted — sentiment × confidence, normalized
     - llm_sentiment_5d — rolling 5d sum of conf-weighted sentiment
     - llm_sentiment_30d — rolling 30d sum
     - llm_insider_buy_5d — count of insider_buy events in 5d window
     - llm_insider_sell_5d — count of insider_sell events in 5d window
     - llm_contract_win_5d — contract wins in 5d window
     - llm_legal_issue_5d — legal issues in 5d window
     - llm_earnings_event_5d — earnings beat/miss/neutral count
     - llm_is_forward_looking — fraction of articles that are forward-looking
     - llm_magnitude_5d — rolling 5d avg magnitude

     NaN fill: 0 (no-news days are genuinely 0 signal)

     Output 2: xs_llm_news_market_daily.parquet

     Grid: (trading_day) — one row per trading day, 100% coverage (ffill gaps)

     Columns:
     - daily_market_tone — mean market_tone across all articles that day
     - daily_market_tone_5d — 5-day rolling mean
     - daily_market_tone_30d — 30-day rolling mean
     - market_tone_momentum — daily_market_tone_5d - daily_market_tone_30d
     - frac_positive_news — fraction of articles with sentiment=1
     - frac_negative_news — fraction of articles with sentiment=-1
     - uncertainty_index — fraction of articles with confidence=0 (high uncertainty
      day)
     - frac_forward_looking — fraction of articles that are forward-looking
     - frac_earnings_news — fraction of articles with earnings event type
     - frac_macro_news — fraction with rate_change/fx_move/macro_indicator/policy_*
     - sector_banking_tone — mean sentiment of articles about banking tickers
     - sector_realestate_tone — mean sentiment of articles about real estate
     tickers
     - sector_tech_tone — mean sentiment of articles about tech tickers
     - event_diversity — number of distinct event_types that day (breadth
     indicator)
     - avg_magnitude — mean magnitude across all articles

     NaN fill: ffill then 0. This gives 100% coverage with no sparsity.

     ---
     WF Integration

     In cross_sectional_wf.py:

     # Flag: --use-llm-news (adds ticker-day columns to feature set)
     # Flag: --use-llm-market (adds date-level columns, merged on date, 100%
     coverage)

     Two separate flags because:
     - Ticker-day features are sparse (same sparsity problem as C1/C2 — useful for
     RL, may hurt XGBoost)
     - Market-daily features are dense (100% coverage — should work in XGBoost)

     The market-daily features are the new dense signal category not previously
     tested.
