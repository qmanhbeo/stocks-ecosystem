## F00007 — Cache parity: missing-date semantics fixed

[link: session_00006.md]

**What**: Fixed pre-computed vs legacy parity gap (~4% absolute return gap).

**Why**: Two issues:
1. `build_liquid_cache()` used `i-4` window vs `check_liquid()` uses `max(0, idx-5)`
2. `check_liquid()` fell back to last date when date missing; precomputed couldn't replicate

**Fix**: 
- Updated `build_cache.py` to use `max(0, idx-5)` window matching check_liquid
- Updated `check_liquid()` to fail-closed (no fallback) matching precomputed
- Rebuilt `liquid_lookup.joblib` - parity now passes

**Rule**: "No exact ticker-date row, no claim." Missing ticker-date must fail closed.
Fallback can create stale/lookahead-like claims. Cache is research logic, not mere optimization.

**Source**: heuristic-trader/notes/session_00006.md
